# iot-kernel 计划格式规范

本文件是 `banyan-plan-draft` 技能的参考文档，描述 iot-kernel 式计划文件的格式标准。

## 文件命名与位置

`plan/YYYY年M月D日-P{N}实施计划.md`（时间+计划号，如 `plan/2026年9月16日-P2P3实施计划.md`），一轮一个，天然归档。

## 文件结构

```
# [P名称] 落地实施计划（YYYY年M月D日）

> 来源：[输入文件/勘察结果]
> 用户决策（已确认）：**[方向描述]**
> 前置基线：[之前阶段的完成状态，如 `cargo test 100通过 / clippy零告警`]
> 本文件为执行跟踪表，随执行情况和结果动态更新状态。

图例：⬜ 待开始 / 🟡 进行中 / ✅ 已完成 / ❌ 受阻 / ⏭️ 跳过（本轮不做，留后轮）。

## 状态总览

| 阶段 | 内容 | 状态 | 备注 |
|------|------|------|------|
| P5-0 | 残留硬伤小修（R1/R2/R3，0.5天） | ⬜ 待开始 | …… |
| P5-1 | MQTT5 完整状态机 | ⬜ 待开始 | …… |

## [阶段号] 拆解

| 子项 | 文件:行号 | 改法 | 状态 |
|------|-----------|------|------|
| P5-1a | `file.rs:123` | 具体改法描述 | ⬜ 待开始 |
| P5-1b | `file.rs:456` | 具体改法描述 | ⬜ 待开始 |

验收：[具体的验证命令和预期结果]

## 验证门禁（每阶段）

`命令1` + `命令2` + `命令3`。

## 延后（本轮不做，仅跟踪）

* P4：……
* P7：……

## 执行日志

* YYYY-MM-DD：建表，开始 XXX。
```

## 状态更新规则

- `⬜` → `🟡`：步骤开始时
- `🟡` → `✅`：门禁全绿后，备注写关键结果
- `🟡` → `❌`：门禁红灯或遇到阻塞
- `⬜` → `⏭️`：用户决定本轮跳过

## 备注列写法（从 iot-kernel 提炼）

- 数量变化：`97→99通过`
- 门禁结果：`fmt clean / clippy零告警`
- 关键决策：`经论证否决`、`暂不做`
- 教训：`复用同一网关会命中去重窗口误判`
