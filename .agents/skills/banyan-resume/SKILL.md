# Banyan 断点恢复技能

你在新会话中接手未完成任务。核心原则：**严禁重新规划，严禁重复已完成步骤**。

## 恢复流程

### 第一步：三读（按顺序）

1. **读 `TASK_PLAN.md`**：获取总体进度（哪些已完成、哪个是当前、哪些待开始）。
2. **读 `EXEC_LOG.md`**：获取最新日志切片（最后 20-30 行），了解最新现场。
3. **读当前轮次的 dated 计划文件**：获取子项拆解和备注详情。

### 第二步：定位断点

在 `TASK_PLAN.md` 中找到：
- 最后一个 `[x]`（已完成）步骤
- 第一个 `[-]`（进行中）或 `[ ]`（待开始）步骤

在 `EXEC_LOG.md` 中找到：
- 最后一条 `步骤 N 已完成` 条目
- 是否有未完成的 `步骤 N 开始` 条目（说明在完成前中断）

### 第三步：汇报断点

向用户输出以下格式的断点报告：

```
## 断点接力报告

任务：[标题]
总体进度：已完成 [N]/[M] 步

最后完成的步骤：步骤 [X] - [描述]
（附：最后日志的关键信息，如"99通过 / clippy零告警"）

当前中断/进行中的步骤：步骤 [Y] - [描述]
下一步应执行的操作：[从 EXEC_LOG.md 最后一条推断]

请确认继续从步骤 [Y] 开始执行。
```

### 第四步：直接继续

确认用户无异议后，直接从断点步骤继续执行，遵守以下规则：
- 不重新规划（不覆盖 `TASK_PLAN.md` 和 dated 计划文件）
- 不重复已完成（`[x]`）的步骤
- 不运行已完成步骤的门禁
- 继续遵守 `banyan-exec-log` 的日志规范

## 约束

- 恢复流程中禁止修改任何代码文件。
- 恢复流程中禁止覆盖 `TASK_PLAN.md` 或 dated 计划文件（除非用户明确要求重新规划）。
- 断点报告必须包含具体的文件变更摘要（从 `EXEC_LOG.md` 最后完成步骤提取），让新会话能理解上下文。
- 如果双轨文件不一致（`TASK_PLAN.md` 和 dated 计划文件状态不同），必须先修一致再继续，修复过程记入 `EXEC_LOG.md`。
- 如果找不到 dated 计划文件，提示用户指定计划文件路径或执行 `banyan-plan-draft` 新建。
